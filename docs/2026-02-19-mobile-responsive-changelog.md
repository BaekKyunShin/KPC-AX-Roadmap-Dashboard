## Batch 0: 글로벌 CSS + 공통 UI 컴포넌트 (2026-02-19)

### 1. 전체 앱 — 한글 줄바꿈 및 미디어 방어

**확인 경로:** 모든 페이지

**기존:** 모바일에서 긴 한글 텍스트가 글자 중간에서 잘려 줄바꿈됨 (예: "교육과정" → "교육과" / "정"). 긴 URL이나 영문이 컨테이너를 뚫고 넘침.

**수정:** 한글은 항상 단어 단위로 줄바꿈됨 ("교육과정"이 통째로 다음 줄로 이동). 긴 URL/영문도 컨테이너 안에서 자동 줄바꿈. 이미지/비디오가 화면 너비를 넘지 않음.

**확인 포인트:**

- 아무 페이지에서 한글 텍스트가 글자 중간에서 끊기지 않는지 확인
- 긴 텍스트가 있는 곳에서 수평 스크롤바가 body에 나타나지 않는지 확인

### 2. 페이지네이션 — 테이블 하단 페이지 이동 버튼

**확인 경로:** 테이블이 있는 모든 페이지 하단 (예: 운영관리 > **사용자 관리**, 워크스페이스 > **프로젝트 관리**, **담당 프로젝트** 목록 등)

**기존:** 버튼(처음/이전/1 2 3/다음/마지막) 터치 영역이 작아 손가락으로 정확히 누르기 어려움. 좌우 패딩이 넓어 320px에서 버튼이 빽빽하게 밀림.

**수정:** 모든 버튼에 최소 높이 36px 적용으로 터치 편의성 확보. 모바일에서 좌우 패딩과 버튼 간격 축소로 공간 확보. 640px 이상에서는 기존과 동일.

**확인 포인트:**

- 페이지 번호 버튼을 손가락으로 편하게 누를 수 있는지 확인
- 버튼들이 겹치거나 잘리지 않는지 확인

### 3. 빈 상태 화면

**확인 경로:** 데이터가 없는 모든 페이지 (예: 프로젝트 0건일 때, 검색 결과 없을 때)

**기존:** 상하 패딩 48px, 아이콘 48x48px 고정. 모바일에서 빈 상태 메시지가 과하게 넓은 여백을 차지.

**수정:** 모바일에서 상하 패딩 32px, 아이콘 40x40px로 축소. 640px 이상에서는 기존 크기 유지.

**확인 포인트:**

- 빈 상태 화면이 모바일 화면에서 자연스러운 비율인지 확인

### 4. 로드맵 생성 로딩 모달

**확인 경로:** **테스트 로드맵** 메뉴 진입 → "로드맵 생성" 버튼 클릭 시 나타나는 로딩 오버레이. 또는 **담당 프로젝트** > 프로젝트 선택 > 로드맵 탭에서 생성 시.

**기존:** 모달 최대 너비 448px 고정 → 320px 폰에서 좌우 여백이 거의 없음. 스텝 라벨("요구사항 분석", "교육과정 설계", "로드맵 구성")이 줄바꿈 금지 → 좁은 화면에서 넘침. 팁 카드 패딩 16px 고정.

**수정:** 모달이 항상 화면 양쪽에 16px 여백 유지. 스텝 라벨이 모바일에서 줄바꿈 허용. 팁 카드 패딩을 모바일에서 12px로 축소. 640px 이상에서는 기존과 동일.

**확인 포인트:**

- 로딩 모달이 화면 좌우 끝에 닿지 않고 여백이 있는지 확인
- 3단계 스텝 라벨이 모두 읽을 수 있는지 확인
- 팁 카드 텍스트가 잘리지 않는지 확인

### 5. 자가진단 결과 항목별 점수

**확인 경로:** 워크스페이스 > **프로젝트 관리** > 프로젝트 선택 → "자가진단 결과" 섹션의 항목별 점수 영역. 또는 **로드맵 갤러리** > 로드맵 선택 → 자가진단 결과 섹션.

**기존:** 차원명(예: "데이터 활용 역량")이 112px 고정 너비 + 말줄임 → 7글자 이상이 "데이터 활용..."처럼 잘림. 점수(85/100)와 퍼센트(85%) 칸도 고정 너비.

**수정:** 모바일에서 차원명이 고정 너비 없이 전체 표시. 점수/퍼센트 칸 너비 축소. 매우 좁은 화면에서 줄바꿈 허용. 640px 이상에서는 기존 고정 너비 + 말줄임 유지.

**확인 포인트:**

- 모든 차원명이 잘리지 않고 완전히 보이는지 확인
- 점수와 퍼센트가 겹치지 않는지 확인
- 프로그레스 바가 정상적으로 표시되는지 확인

### 데스크톱 보호 확인

**확인 경로:** 위 5개 항목의 모든 페이지를 1024px 이상에서 확인

**확인 포인트:**

- 페이지네이션 버튼 크기/간격이 기존과 동일한지 확인
- 빈 상태 화면 패딩/아이콘 크기가 기존과 동일한지 확인
- 로딩 모달 너비가 기존 448px 그대로인지 확인
- 자가진단 차원명이 기존처럼 고정 너비 + 말줄임인지 확인

## Batch 1: Auth + 공통 대시보드 + Public 페이지 (2026-02-19)

### 1. 승인 대기 카드 — 진행 단계 표시

**확인 경로:** 승인 대기 중인 컨설턴트/운영관리자로 로그인 → **대시보드** 메인 화면

**기존:** 진행 단계(4개)가 수평으로 나열되어 320px 화면에서 아이콘과 텍스트("가입 완료", "프로필 검토", "승인 완료", "서비스 이용")가 겹치거나 잘림. 연결선이 공간을 더 압박.

**수정:** 모바일에서 2x2 그리드로 배치되어 각 단계가 충분한 공간을 확보. 연결선은 모바일에서 숨김. 640px 이상에서는 기존 수평 배열 + 연결선 복원.

**확인 포인트:**

- 320px에서 4단계가 2x2 그리드로 깔끔하게 배치되는지 확인
- 운영관리자(3단계)도 그리드에서 자연스럽게 표시되는지 확인
- 640px 이상에서 기존 수평 레이아웃 + 연결선이 그대로인지 확인

### 2. 승인 대기 카드 — 프로필 수정 배너

**확인 경로:** 승인 대기 중 컨설턴트 + 프로필 있는 경우 → 대시보드의 "프로필 수정" 배너

**기존:** 텍스트와 "프로필 수정" 버튼이 같은 줄에 배치되어 320px에서 밀착됨.

**수정:** flex-wrap 적용으로 320px에서 버튼이 자연스럽게 아래로 내려감. 640px 이상에서는 기존 한 줄 배치 유지.

**확인 포인트:**

- 320px에서 텍스트와 버튼이 겹치지 않는지 확인

### 3. 데모 페이지 — 헤더 내비게이션

**확인 경로:** 로그아웃 상태 → **데모** 페이지 상단 헤더

**기존:** "KPC AI 로드맵" 로고 뒤에 "데모 화면" 배지 마진 16px + 로그인/회원가입 버튼 간격 16px → 320px에서 요소가 빽빽하거나 줄 뜸.

**수정:** 배지 마진 8px으로 축소, 버튼 간격 8px으로 축소, 회원가입 버튼 패딩 축소. 640px 이상에서는 기존 크기 유지.

**확인 포인트:**

- 320px에서 헤더 요소가 한 줄에 들어가는지 확인
- 로그인/회원가입 텍스트가 잘리지 않는지 확인

### 4. 데모 페이지 — 로드맵 탭

**확인 경로:** **데모** 페이지 → 로드맵 영역의 탭 (행렬 리포트 / 교육과정 / PBL 과정)

**기존:** 탭 패딩 px-6 py-4 고정 + overflow 처리 없음 → 320px에서 탭이 화면을 넘어 body 수평 스크롤 발생.

**수정:** 모바일에서 탭 패딩 축소(px-3 py-2), 텍스트 크기 축소(text-xs), 탭 컨테이너에 가로 스크롤 추가. 640px 이상에서는 기존 크기 유지.

**확인 포인트:**

- 320px에서 탭이 가로 스크롤 가능하고 body 수평 스크롤은 없는지 확인
- 탭 텍스트가 모두 읽을 수 있는지 확인
- 탭 클릭/터치가 정상 동작하는지 확인

### 5. 변경 불필요 확인 (6개 파일)

다음 파일들은 확인 결과 이미 모바일 대응이 양호하여 수정하지 않음:

- **로그인 페이지** (`login/page.tsx`): `p-4`, `max-w-md` 양호. globals.css break-keep 적용.
- **회원가입 페이지** (`register/page.tsx`): `sm:grid-cols-2` 양호.
- **대시보드 메인** (`dashboard/page.tsx`): PendingApprovalCard 내부에서 해결.
- **프로필 폼** (`ProfileForm.tsx`): 부모 대시보드 레이아웃에 `px-4` 이미 적용되어 추가 패딩 불필요.
- **갤러리 카드** (`GalleryCard.tsx`): `flex-wrap`, `line-clamp-2` 양호.
- **갤러리 상세** (`gallery/[id]/page.tsx`): `flex flex-wrap items-center gap-2` 양호.

### 데스크톱 보호 확인

**확인 경로:** 위 4개 항목의 페이지를 1024px 이상에서 확인

**확인 포인트:**

- 승인 대기 카드 진행 단계가 기존 수평 배열 + 연결선 그대로인지 확인
- 데모 헤더 마진/간격이 기존과 동일한지 확인
- 데모 탭 패딩/크기가 기존과 동일한지 확인

## Batch 2: 컨설턴트 영역 (테이블 + 카드) (2026-02-19)

### 1. 컨설턴트 홈 — SummaryCards 그리드 비대칭 해결

**확인 경로:** 컨설턴트로 로그인 → **컨설턴트 홈** 화면 상단 숫자 카드 5개

**기존:** 5개 카드가 `grid-cols-2` 2열 배치 → 마지막 "로드맵 완료" 카드 1개만 홀로 왼쪽에 남아 오른쪽이 비어있는 비대칭 레이아웃.

**수정:** 마지막 카드에 `col-span-2 lg:col-span-1` 조건부 적용. 모바일 2열에서 마지막 카드가 전체 너비를 차지하여 균형 잡힌 레이아웃. lg(1024px) 이상에서는 기존 5열 유지.

**확인 포인트:**

- 320px에서 마지막 카드("로드맵 완료")가 전체 너비로 표시되는지 확인
- 나머지 4개 카드가 2x2로 균일하게 배치되는지 확인
- 1024px 이상에서 5개 카드가 한 줄에 동일 크기로 표시되는지 확인

### 2. 컨설턴트 프로젝트 목록 — 모바일 카드 뷰 추가

**확인 경로:** 컨설턴트로 로그인 → **담당 프로젝트** 목록

**기존:** 6컬럼 테이블(`min-w-[700px]`)이 모바일에서 가로 스크롤만 가능. 320px 화면에서 테이블 전체를 보려면 좌우로 스크롤해야 하며, 정보 파악이 어려움.

**수정:** md(768px) 미만에서 테이블 대신 카드 뷰로 전환. 각 카드에 기업명+상태 배지(헤더), 업종/규모/배정일(2열 그리드 본문), 상세 보기 링크(푸터) 구성. md 이상에서는 기존 테이블 그대로 표시.

**확인 포인트:**

- 320px에서 프로젝트가 카드 형태로 세로 나열되는지 확인
- 카드 내 기업명, 상태 배지, 업종/규모/배정일 정보가 모두 보이는지 확인
- "상세 보기" 링크가 터치 가능하고 정상 동작하는지 확인
- 768px 이상에서 기존 6컬럼 테이블이 그대로 표시되는지 확인
- 검색/필터 후 카드 뷰에서도 필터된 결과가 정상 표시되는지 확인

### 3. 배정 탭 섹션 — 모바일 간격 축소

**확인 경로:** 운영관리 > **프로젝트 관리** > 프로젝트 선택 → "컨설턴트 배정" 섹션 (배정된 컨설턴트가 있는 경우)

**기존:** 배정된 컨설턴트 정보 영역의 요소 간 간격(gap) 12px 고정.

**수정:** 모바일에서 간격 8px로 축소, 640px 이상에서 기존 12px 유지.

**확인 포인트:**

- 320px에서 배정 정보가 좁은 화면에서도 겹치지 않고 정상 표시되는지 확인

### 4. 변경 불필요 확인 (2개 파일)

다음 파일들은 확인 결과 이미 모바일 대응이 양호하여 수정하지 않음:

- **프로젝트 상세 페이지** (`consultant/projects/[id]/page.tsx`): `lg:grid-cols-5` 그리드, 모바일 1열 이미 양호. globals.css break-keep 적용.
- **컨설턴트 프로필 페이지** (`consultant/profile/page.tsx`): Batch 1에서 부모 대시보드 레이아웃 px-4 이미 적용 확인.

### 데스크톱 보호 확인

**확인 경로:** 위 3개 항목의 페이지를 1024px 이상에서 확인

**확인 포인트:**

- SummaryCards 5개 카드가 한 줄 5열로 동일 크기 표시되는지 확인
- 프로젝트 목록 테이블이 6컬럼 그대로 정상 표시되는지 확인
- 배정 섹션 간격이 기존과 동일한지 확인

## Batch 3: Ops 테이블 Part 1 — 프로젝트 + 사용자 (2026-02-19)

### 1. Ops 프로젝트 목록 — 모바일 카드 뷰 추가

**확인 경로:** 운영관리 > **프로젝트 관리** 목록

**기존:** 6컬럼 테이블(`min-w-[900px]`)이 모바일에서 가로 스크롤만 가능. 320px 화면에서 테이블 전체를 보려면 좌우로 스크롤해야 하며, 정보 파악이 어려움.

**수정:** md(768px) 미만에서 테이블 대신 카드 뷰로 전환. 각 카드에 기업명+이메일(헤더), 업종/컨설턴트/생성일(2열 그리드), MiniStepper 진행 상태(하단 전체 너비) 구성. md 이상에서는 기존 테이블 그대로 표시.

**확인 포인트:**

- [ ] 320px에서 프로젝트가 카드 형태로 세로 나열되는지 확인
- [ ] 카드 내 MiniStepper가 정상 표시되는지 확인
- [ ] 상세보기 링크가 동작하는지 확인
- [ ] 768px 이상에서 기존 6컬럼 테이블이 그대로 표시되는지 확인

### 2. Ops 통계 요약 카드 — 모바일 가로 스크롤

**확인 경로:** 운영관리 > **프로젝트 관리** 상단 통계 카드

**기존:** 7개 카드가 `grid-cols-2`로 모바일에서 마지막 1개가 홀로 남아 비대칭.

**수정:** 모바일에서 가로 스크롤 카드로 전환. 각 카드 120px 최소 너비, 스냅 포인트 적용. 640px 이상에서는 기존 그리드 복원.

**확인 포인트:**

- [ ] 320px에서 통계 카드가 가로 스크롤 가능한지 확인
- [ ] 스크롤 시 카드에 스냅이 동작하는지 확인
- [ ] 640px 이상에서 기존 4열/7열 그리드가 유지되는지 확인

### 3. MiniStepper — 모바일 줄바꿈 허용

**확인 경로:** 운영관리 > **프로젝트 관리** 목록의 진행 상태 (데스크톱 테이블 + 모바일 카드 내부)

**기존:** 상태 라벨이 줄바꿈 금지(`whitespace-nowrap`)로 좁은 화면에서 넘침.

**수정:** 모바일에서 줄바꿈 허용(`sm:whitespace-nowrap`). 640px 이상에서는 기존대로 유지.

**확인 포인트:**

- [ ] 모바일 카드 내부에서 MiniStepper 라벨이 넘치지 않는지 확인

### 4. 사용자 관리 — 모바일 카드 뷰 추가

**확인 경로:** 운영관리 > **사용자 관리** 목록

**기존:** 6컬럼 테이블(`min-w-[700px]`)이 모바일에서 가로 스크롤만 가능. `pl-20`(80px 좌측 패딩)이 모바일에서 과도.

**수정:** md 미만에서 카드 뷰로 전환. 각 카드에 사용자명+역할 배지(헤더), 이메일/전화번호/상태/가입일(2열 그리드), 프로필 보기+관리 액션(푸터) 구성. 테이블 좌측 패딩을 모바일에서 16px로 축소(`pl-4 md:pl-20`).

**확인 포인트:**

- [ ] 320px에서 사용자가 카드 형태로 세로 나열되는지 확인
- [ ] 카드에서 "승인"/"정지"/"활성화" 버튼이 정상 동작하는지 확인
- [ ] 프로필 보기 클릭 시 모달이 정상 표시되는지 확인
- [ ] 768px 이상에서 기존 6컬럼 테이블이 그대로 표시되는지 확인

### 데스크톱 보호 확인

**확인 경로:** 위 4개 항목의 페이지를 1024px 이상에서 확인

**확인 포인트:**

- [ ] 프로젝트 목록 테이블이 6컬럼 그대로 정상 표시되는지 확인
- [ ] 통계 카드가 sm 4열, lg 7열 그리드로 표시되는지 확인
- [ ] MiniStepper 라벨이 한 줄로 유지되는지 확인
- [ ] 사용자 관리 테이블이 6컬럼 + pl-20 패딩 그대로인지 확인
