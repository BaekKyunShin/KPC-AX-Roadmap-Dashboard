# 결과물 제출 기능 설계

> 작성일: 2026-04-11
> 상태: 설계 검토 중

## 1. 개요

로드맵 확정(FINALIZED) 이후 **증빙 서류 제출 → 프로젝트 완료(COMPLETED)** 처리를 위한 기능.

```
┌─────────────────────────────────────────────────────────────────┐
│                        전체 흐름 요약                            │
│                                                                 │
│  운영관리자                    컨설턴트                           │
│  ┌──────────┐                 ┌──────────────────────────────┐  │
│  │ 서류 템플릿 │─── 정의 ──→   │ 프로젝트에 체크리스트 자동 생성  │  │
│  │ 관리      │                └──────────┬───────────────────┘  │
│  └──────────┘                           │                       │
│                                         ▼                       │
│                                 ┌──────────────┐               │
│                                 │  서류 업로드   │               │
│                                 │  (항목별 파일)  │               │
│                                 └──────┬───────┘               │
│                                        │                        │
│                                        ▼                        │
│                              필수 서류 모두 완료?                  │
│                                 │          │                    │
│                                아니오       예                    │
│                                 │          │                    │
│                                 ▼          ▼                    │
│                              계속 업로드   최종 제출               │
│                                           │                    │
│  ┌──────────┐                             │                    │
│  │ 현황 조회  │◀── 상태 반영 ──────────────┘                    │
│  │ + 다운로드 │         FINALIZED → COMPLETED                   │
│  └──────────┘                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 핵심 규칙

- **승인 불필요** — 컨설턴트가 제출하면 자동 완료
- **철회 가능** — 제출 철회 시 `COMPLETED → FINALIZED` 복귀
- **서류 종류는 동적** — 운영관리자가 관리 화면에서 설정 (코드 변경 불필요)

## 2. 프로젝트 상태 전환

```
기존:
  NEW → DIAGNOSED → MATCH_RECOMMENDED → ASSIGNED → INTERVIEWED
    → ROADMAP_DRAFTED → FINALIZED

변경:
  NEW → DIAGNOSED → MATCH_RECOMMENDED → ASSIGNED → INTERVIEWED
    → ROADMAP_DRAFTED → FINALIZED → COMPLETED
                                       ↑            │
                                       └── 철회 ────┘
```

| 전환 | 트리거 | 조건 |
|------|--------|------|
| FINALIZED → COMPLETED | 컨설턴트 "최종 제출" | 모든 필수 서류 UPLOADED |
| COMPLETED → FINALIZED | 컨설턴트 "제출 철회" | 언제든 가능 |

- `projects` 테이블에 `submitted_at` (TIMESTAMPTZ) 컬럼 추가
- 제출 시 현재 시각 기록, 철회 시 NULL로 초기화

### 체크리스트 생성 시점

프로젝트가 **ASSIGNED** 상태로 전환될 때, 현재 `is_active = true`인 템플릿을 기반으로 `project_deliverables` 레코드를 자동 생성한다.

→ 인터뷰 중 현장 사진, 회의록 등을 바로 업로드할 수 있도록 일찍 생성

### 제출 조건

```
모든 필수 서류(is_required = true)의 status = 'UPLOADED'
  → "최종 제출" 버튼 활성화
  → 클릭 시 project.status = 'COMPLETED', project.submitted_at = NOW()
```

- 하단: "최종 제출" 버튼 (필수 항목 모두 완료 시 활성화)
- 제출 후: 배너 녹색 전환 + "제출 철회" 버튼 표시

### 5-2. 컨설턴트 — 결과물 관리 페이지

경로: `/consultant/results`

```
┌──────────────────────────────────────────────────────────────────────┐
│  결과물 관리                                                          │
│                                                                      │
│  ┌───────────┐  ┌───────────┐  ┌───────────┐                        │
│  │  전체  12  │  │ 미제출  5  │  │ 제출완료 7 │                        │
│  └───────────┘  └───────────┘  └───────────┘                        │
│                                                                      │
│  [ 전체 ▾ ] [ 미제출 ] [ 제출완료 ]              🔍 기업명 검색       │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────────┐ │
│  │ 기업명         │ 프로젝트 상태  │ 필수 서류  │ 제출일             │ │
│  ├──────────────────────────────────────────────────────────────────┤ │
│  │ ㈜한국전자     │ COMPLETED     │ ████░ 4/4 │ 2026-04-10        │ │
│  │ 대한물산㈜     │ FINALIZED     │ ██░░░ 2/4 │ —                 │ │
│  │ 미래테크       │ FINALIZED     │ ░░░░░ 0/4 │ —                 │ │
│  │ 글로벌솔루션   │ COMPLETED     │ ████░ 4/4 │ 2026-04-08        │ │
│  │ ...            │               │           │                   │ │
│  └──────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  행 클릭 → 해당 프로젝트 상세 > 결과물 탭으로 이동                     │
└──────────────────────────────────────────────────────────────────────┘
```

**동작 요약:**
- 상단 요약 카드: 전체 / 미제출 / 제출완료 건수
- 필터 탭 + 기업명 검색
- 필수 서류 진행률을 프로그레스 바로 표시
- 행 클릭 시 프로젝트 상세 결과물 탭으로 이동
- FINALIZED 이상인 프로젝트만 표시 (서류 제출 대상)

**결과물 탭 노출 조건:**
- 프로젝트 상세의 "결과물" 탭은 **ASSIGNED 이상** 상태에서 표시 (체크리스트 생성 시점과 일치)
- 단, "최종 제출" 버튼은 **FINALIZED** 상태일 때만 활성화
- 결과물 관리 조감 페이지는 **FINALIZED 이상**만 표시 (제출 추적 목적)

│  ≡ = 드래그 정렬 핸들                                                 │
│  ✏️ = 수정/삭제 (모달)                                                │
│  비활성화 시: 기존 프로젝트는 유지, 신규 프로젝트에만 미적용             │
└──────────────────────────────────────────────────────────────────────┘

## 6. RLS 정책

| 테이블 | SELECT | INSERT/UPDATE/DELETE |
|--------|--------|---------------------|
| deliverable_templates | 모든 인증 사용자 | OPS_ADMIN, SYSTEM_ADMIN만 |
| project_deliverables | 담당 컨설턴트 + OPS_ADMIN + SYSTEM_ADMIN | 담당 컨설턴트만 (CUD) |
| deliverable_files | 담당 컨설턴트 + OPS_ADMIN + SYSTEM_ADMIN | 담당 컨설턴트만 (CUD) |

- "담당 컨설턴트" = `projects.assigned_consultant_id = auth.uid()`
- OPS_ADMIN/SYSTEM_ADMIN은 전체 조회 + 다운로드 가능, 수정 불가
- Storage 버킷 정책도 동일 패턴 적용

## 7. Server Actions

| Action | 위치 | 역할 |
|--------|------|------|
| `uploadDeliverableFile` | consultant/projects/[id]/actions.ts | 파일 업로드 + deliverable status → UPLOADED |
| `deleteDeliverableFile` | consultant/projects/[id]/actions.ts | 파일 삭제 (마지막 파일이면 status → PENDING) |

| `submitDeliverables` | consultant/projects/[id]/actions.ts | 최종 제출 (project → COMPLETED) |
| `withdrawSubmission` | consultant/projects/[id]/actions.ts | 제출 철회 (project → FINALIZED) |
| `createTemplate` | ops/templates/actions.ts | 서류 템플릿 생성 |
| `updateTemplate` | ops/templates/actions.ts | 서류 템플릿 수정 |
| `deleteTemplate` | ops/templates/actions.ts | 서류 템플릿 삭제 |
| `downloadDeliverableZip` | API Route (스트리밍) | 전체 파일 ZIP 다운로드 |
