## 조사 범위

아래 영역을 빠짐없이 살펴봐:

1. **랜딩 페이지** — 히어로, 기능 소개, 워크플로우, 데모, 푸터
2. **인증 플로우** — 로그인, 회원가입, 승인 대기 안내
3. **공통 대시보드** — 홈, 프로필, 계정 설정
4. **DM 메시징** — 대화 목록, 메시지 입력, 실시간 UX
5. **컨설턴트 영역** — 대시보드(KPI 카드, 차트), 프로필 관리, 담당 프로젝트 목록
6. **프로젝트 상세** — 기업 정보 카드, 탭 구조, 인터뷰 가이드, 활동 로그
7. **현장 인터뷰** — 6단계 스테퍼 폼 (기본정보→기업상세→직무과업→제약목표→고충→요약)
8. **로드맵** — 매트릭스 뷰, PBL 뷰, 과정 목록, 버전 히스토리, PDF/XLSX 내보내기
9. **운영관리(OPS)** — 프로젝트 관리(대시보드+타임라인+테이블), 사용자 관리, 쿼터 관리, 감사로그, 자가진단 템플릿
10. **컨설턴트 배정** — 자동매칭 추천, 수동배정, 자가진단 폼
11. **갤러리** — 로드맵 카드 그리드, 좋아요, 공유, "이 로드맵 사용" 다이얼로그
12. **테스트 로드맵** — 연습용 로드맵 생성 폼 + 결과
13. **네비게이션** — 사이드바/탑바, 메뉴 구조, 모바일 햄버거 메뉴
14. **알림 시스템** — NotificationBell, 알림 표시 방식
15. **공통 패턴** — 테이블(정렬/필터/페이지네이션), 폼(라벨/에러/제출), 모달, 토스트, 빈 상태, 로딩 스켈레톤

## 분석 관점

각 영역에서 아래 관점으로 분석해줘:

- **정보 구조(IA):** 메뉴 계층, 라벨링, 사용자가 원하는 기능을 찾기까지의 경로
- **인터랙션 디자인:** 클릭 횟수, 피드백(로딩/성공/에러), 되돌리기 가능성
- **시각적 일관성:** 색상, 타이포그래피, 간격, 컴포넌트 스타일의 통일성
- **비어 있는 상태 & 온보딩:** 데이터 없을 때의 가이드, 첫 사용자 경험
- **접근성:** 키보드 탐색, 색상 대비, ARIA 라벨, 포커스 관리
- **마이크로 인터랙션:** 호버, 전환 애니메이션, 상태 변화 피드백
- **모바일 UX:** 터치 타겟, 스크롤, 모바일 전용 레이아웃

## 참고할 외부 레퍼런스

B2B SaaS 대시보드 중 UX가 뛰어난 서비스들을 기준으로 비교 분석해줘:
- Linear (프로젝트 관리)
- Notion (정보 구조)
- Vercel Dashboard (개발자 대시보드)
- Stripe Dashboard (데이터 테이블 & 필터)
- Figma (협업 & 온보딩)
- Mixpanel / Amplitude (분석 대시보드)

각 개선안에서 "XX 서비스의 YY 패턴을 참고" 식으로 구체적 레퍼런스를 명시해줘.

## 출력 형식

**개선안 5개**를 아래 형식으로 정리해줘. 가장 임팩트가 큰 것부터 우선순위 순으로:

### 개선안 N: [한 줄 제목]

**위치:** 사용자 관점의 메뉴 경로 (예: 운영관리 > 프로젝트 관리 > 대시보드 탭)
**해당 파일:** `src/app/...` 또는 `src/components/...`
**현재 문제:** 현재 UX의 구체적 문제점
**개선 방향:** 어떻게 바꾸면 좋은지 구체적으로 설명
**참고 레퍼런스:** XX 서비스의 YY 패턴

**현재 vs 개선안 시각 비교:**

```

[현재]
┌─────────────────────────┐
│  현재 UI의 ASCII 와이어프레임  │
└─────────────────────────┘

[개선안]
┌─────────────────────────┐
│  개선된 UI의 ASCII 와이어프레임  │
└─────────────────────────┘

```

**기대 효과:** 사용자 경험이 어떻게 나아지는지 1~2문장

## 주의사항

- 단순 "색상을 바꿔라" 같은 피상적 제안은 제외하고, 사용자 행동에 실질적 영향을 주는 것만 포함해줘
- 현재 이미 잘 되어 있는 부분은 "잘된 점"으로 별도 섹션에 간단히 언급해줘
- 각 개선안의 구현 난이도도 표시해줘 (🟢 쉬움 / 🟡 보통 / 🔴 어려움)
- ASCII 와이어프레임은 최소 폭 60자 이상으로, 실제 레이아웃을 알아볼 수 있게 그려줘

## 프롬프트 설계 의도

| 설계 요소 | 이유 |
|-----------|------|
| 조사 범위 15개 영역 명시 | 빠짐없이 전수조사하도록 구체적 체크리스트 제공 |
| 분석 관점 7가지 | 단순 비주얼이 아닌 UX 전문가 수준의 다각도 분석 유도 |
| 외부 레퍼런스 6개 | 추상적 "좋은 UX"가 아닌 구체적 벤치마크 기준 제시 |
| 출력 형식 고정 | 위치/파일/문제/개선/레퍼런스/시각비교를 빠짐없이 받기 위해 |
| ASCII 와이어프레임 | 시각적 비교를 CLI 환경에서 표현 가능한 형태로 요청 |
| 5~10개 제한 | 너무 많으면 산만, 임팩트 큰 것에 집중하도록 |
| 구현 난이도 표시 | 우선순위 판단에 활용 |
| "잘된 점" 포함 | 균형 잡힌 분석 + 이미 좋은 패턴 보존 유도 |
