# KPC AI 훈련 로드맵 대시보드 — UX/UI 전수조사 보고서

> 작성일: 2026-02-21
> 조사 범위: 코드베이스 전체 15개 영역, 7가지 분석 관점
> 참고 레퍼런스: Linear, Notion, Vercel, Stripe, Figma, Mixpanel/Amplitude

## 잘된 점

종합 분석 결과, 이 프로젝트는 B2B 내부 도구로서 높은 수준의 UX 기반을 갖추고 있습니다.

| 영역 | 잘된 점 |
|------|---------|
| **인터뷰 6단계 폼** | 3초 디바운스 자동 저장 + JSON 비교 변경 감지 + 완화/엄격 스키마 이중 검증. 예제 데이터 "채우기" 버튼으로 입력 가이드 제공 |
| **역할 기반 메뉴** | 컨설턴트는 플랫 4개 메뉴, 관리자는 드롭다운 3그룹으로 복잡도 분리 |
| **실시간 메시징** | Supabase Realtime + 지수 백오프 재시도 + 10초 폴링 폴백. `useLayoutEffect`로 스크롤 점프 방지 |
| **반응형 듀얼 뷰** | 모든 테이블이 데스크톱(테이블) / 모바일(카드) 이중 렌더링 |
| **로드맵 매트릭스** | 데스크톱 테이블 → 모바일 탭+카드 전환. 난이도별 색상 코딩 |
| **랜딩 페이지** | GSAP + Lenis 프리미엄 애니메이션, 체계적 색상·간격·타이포 |
| **갤러리 좋아요** | `useTransition` 낙관적 업데이트 + 실패 시 자동 롤백 |
| **감사로그** | 20종 액션 타입 완벽 추적 + Excel 내보내기(최대 10,000건) |
| **알림 무한 스크롤** | `IntersectionObserver` + Ref 기반 동시성 방지 |
| **폼 검증 일관성** | 모든 Server Action이 Zod 스키마 → 역할 검증 → 비즈니스 로직 → `ActionResult<T>` 패턴 |

## 개선안 1: OPS 프로젝트 목록에 사이드 패널 퀵뷰 도입 🔴 어려움

**위치:** 운영관리 > 프로젝트 관리 > 목록 탭
**해당 파일:** `src/app/(dashboard)/ops/projects/_components/ProjectList.tsx`, `src/app/(dashboard)/ops/projects/[id]/page.tsx`

**현재 문제:**
관리자가 50개 이상의 프로젝트를 관리할 때, 프로젝트 현황을 파악하려면 **목록 클릭 → 상세 페이지 전체 로드 → 4개 탭 탐색 → 뒤로가기 → 다음 프로젝트 반복**이라는 과정을 거쳐야 합니다. `ProjectList.tsx`에서 테이블 행을 클릭하면 `router.push(/ops/projects/${id})`로 전체 페이지 이동이 발생하며, 목록의 필터·검색·스크롤 위치가 모두 초기화됩니다. 컨설턴트 배정 여부, 인터뷰 진행 상태, 로드맵 생성 여부를 빠르게 훑어보려면 프로젝트마다 2~3번의 전체 페이지 전환이 필요합니다.

**개선 방향:**
테이블 행 클릭 시 **오른쪽 사이드 패널(드로어)**이 열리면서 프로젝트 요약 정보를 표시합니다. 패널 내에서 키보드 ↑/↓로 이전/다음 프로젝트를 탐색할 수 있고, 패널을 닫지 않고도 "상세 보기" 링크로 전체 페이지 이동이 가능합니다. 목록의 필터·스크롤 상태는 유지됩니다.

**참고 레퍼런스:** Stripe Dashboard의 **Detail Drawer 패턴** — 결제 목록에서 행을 클릭하면 우측 드로어가 열리면서 결제 상세, 타임라인, 관련 이벤트를 한눈에 보여줍니다. Stripe는 드로어 내에서 키보드 탐색과 인라인 액션도 지원합니다.

**현재 vs 개선안 시각 비교:**

## 개선안 2: 역할별 온보딩 체크리스트 & 승인 대기 경험 🟡 보통

**위치:** 회원가입 직후 → 대시보드 최초 진입
**해당 파일:** `src/app/(auth)/register/page.tsx`, `src/app/(dashboard)/dashboard/page.tsx`, `src/app/(dashboard)/consultant/home/page.tsx`

**현재 문제:**
회원가입 후 `USER_PENDING` 또는 `OPS_ADMIN_PENDING` 상태의 사용자에 대한 **승인 대기 안내 화면이 없습니다.** `register/page.tsx`에서 가입 완료 후 자동 로그인을 시도하지만, 승인이 완료되지 않은 사용자가 대시보드에 접근하면 빈 화면이나 권한 오류를 만날 수 있습니다. 또한 승인된 컨설턴트가 처음 로그인했을 때 프로필을 완성하고 → 프로젝트를 확인하고 → 인터뷰를 시작하는 순서를 알 수 있는 가이드가 없습니다. `consultant/home/page.tsx`의 SummaryCards가 모두 0인 상태로 표시될 뿐입니다.

**개선 방향:**
1. **승인 대기 화면**: 가입 직후 "승인 대기 중" 전용 페이지를 표시. 예상 승인 시간, 관리자 연락처, 승인 알림 안내를 포함.
2. **온보딩 체크리스트**: 최초 로그인 시 대시보드 상단에 4단계 체크리스트를 표시 (프로필 완성 → 담당 프로젝트 확인 → 첫 인터뷰 완료 → 로드맵 생성). 프로그레스 바를 25%에서 시작하여 완료 편향(endowed progress effect) 활용.
3. **빈 상태 CTA 강화**: 프로젝트 0건일 때 단순 "없습니다" 대신 "관리자가 프로젝트를 배정하면 여기에 표시됩니다" + 프로필 완성 CTA.

**참고 레퍼런스:** Figma의 **선택적 온보딩 투어** — 사용자에게 투어 참여를 선택하게 하고, 각 툴팁에 애니메이션 데모 + "더 알아보기" 링크를 포함. ProductLed의 **온보딩 체크리스트 패턴** — 4단계 + 프로그레스 바를 20%에서 시작.

## 개선안 3: 글로벌 커맨드 팔레트 (CMD+K) 🟡 보통

**위치:** 전체 앱 (대시보드 내 모든 페이지)
**해당 파일:** `src/components/ui/Navigation.tsx` (트리거 위치), 신규 `src/components/ui/CommandPalette.tsx`

**현재 문제:**
현재 네비게이션은 **마우스 기반 메뉴 탐색만 지원**합니다. `Navigation.tsx`에서 컨설턴트는 4개 메뉴, 관리자는 3개 드롭다운 그룹을 클릭해야 합니다. 특정 프로젝트(예: "삼성전자 AI 교육")를 찾으려면 프로젝트 목록 페이지로 이동 → 검색창에 입력 → 결과 클릭이라는 3단계가 필요합니다. 관리자가 "A컨설턴트의 담당 프로젝트"를 보려면 사용자 관리 → 프로필 확인 → 프로젝트 관리 → 필터 설정이라는 4단계를 거칩니다. 키보드 단축키도 없어 파워 유저의 생산성이 제한됩니다.

**개선 방향:**
`CMD+K` (Mac) / `Ctrl+K` (Windows)로 열리는 커맨드 팔레트를 도입합니다. 검색 범위: 프로젝트(기업명), 사용자(이름/이메일), 페이지(메뉴명), 액션(프로젝트 생성, 사용자 승인 등). 최근 사용 항목을 상단에 표시하고, 카테고리별 필터 탭을 제공합니다.

**참고 레퍼런스:** Linear의 **커맨드 메뉴** — 단순 검색이 아닌 "액션 실행"이 목적. 이슈 생성, 상태 변경, 페이지 이동을 모두 한 인터페이스에서 수행. 최근 사용 명령을 상단에 표시하여 반복 작업 가속화.

**현재 vs 개선안 시각 비교:**

```

┌──────────────────────────────────────────────────────────┐
```

## 개선안 4: 테이블 필터 통합 칩 패턴 & 필터 프리셋 🟢 쉬움

**위치:** 운영관리 > 프로젝트 관리 / 사용자 관리 / 감사로그 / 쿼터 관리
**해당 파일:** `src/app/(dashboard)/ops/projects/_components/ProjectList.tsx`, `src/app/(dashboard)/ops/audit/page.tsx`, `src/app/(dashboard)/ops/users/page.tsx`, `src/app/(dashboard)/ops/quota/page.tsx`

**현재 문제:**
OPS 영역의 4개 테이블이 **각각 다른 필터 UI 패턴**을 사용합니다:
- `ProjectList.tsx`: 검색(flex-1) + 상태 Select + 업종 Select → 활성 필터를 Badge+X 버튼으로 표시
- `audit/page.tsx`: 검색 + 액션 Select + 대상타입 Select + 사용자 Select + 날짜 범위 2개 → 별도 리셋 버튼
- `users/page.tsx`: 검색만 (필터 없음)
- `quota/page.tsx`: 월 선택 Select만

필터 컴포넌트의 높이, 간격, 정렬 방식도 페이지마다 다릅니다. 감사로그 필터는 6개 컨트롤이 한 줄에 줄세워져 있어 모바일에서 `flex-wrap`으로 떨어지면서 어떤 필터가 어떤 컬럼에 해당하는지 파악하기 어렵습니다.

**개선 방향:**
모든 테이블에 **통합 필터 바** 컴포넌트를 도입합니다. 기본 상태에서는 검색창 + "필터 추가" 버튼만 표시하고, 버튼 클릭 시 필터 카테고리(상태, 역할, 날짜 등)를 선택할 수 있는 드롭다운이 열립니다. 적용된 필터는 **칩(Chip)**으로 검색창 아래에 표시되며, 각 칩의 X 버튼으로 개별 제거할 수 있습니다. 자주 사용하는 필터 조합을 "프리셋"으로 저장하는 기능도 추가합니다.

**참고 레퍼런스:** Stripe Dashboard의 **필터 칩 패턴** — 필터 적용 시 칩으로 현재 필터를 시각화하고, "모두 선택/해제" 및 필터 내 검색 기능으로 대량 데이터 대응. 필터는 항상 제어 대상 컬럼 가까이에 배치.

**현재 vs 개선안 시각 비교:**

```
[현재 — 감사로그 필터 (6개 컨트롤이 한 줄에)]
┌──────────────────────────────────────────────────────────┐
│ ┌──────────┐┌────────┐┌──────────┐┌──────┐┌──────┐┌────┐│
│ │🔍 검색   ││ 액션 ▾ ││ 대상타입 ▾││사용자▾││시작일││종료││
│ └──────────┘└────────┘└──────────┘└──────┘└──────┘└────┘│
│                                                          │
│ ← 모바일에서 flex-wrap 시 어떤 필터가 뭔지 파악 어려움 →    │
└──────────────────────────────────────────────────────────┘

[현재 — 프로젝트 목록 필터 (다른 패턴)]
┌──────────────────────────────────────────────────────────┐
│ ┌──────────────────────┐  ┌──────────┐  ┌──────────┐    │
│ │ 🔍 프로젝트 검색      │  │ 상태 ▾   │  │ 업종 ▾   │    │
│ └──────────────────────┘  └──────────┘  └──────────┘    │
│ [진행중 ✕]  [제조 ✕]                                     │
└──────────────────────────────────────────────────────────┘

[개선안 — 통합 필터 바 (모든 테이블 공통)]
┌──────────────────────────────────────────────────────────┐
│ ┌──────────────────────────────────┐  ┌──────────────┐  │
│ │ 🔍 검색...                       │  │ + 필터 추가  │  │
│ └──────────────────────────────────┘  └──────┬───────┘  │
│                                              │          │
│ 적용된 필터:                          ┌──────┴───────┐  │
│ ┌──────────┐ ┌─────────────┐        │ 상태         │  │
│ │상태: 배정 ✕│ │업종: 제조 ✕  │        │ 역할         │  │
│ └──────────┘ └─────────────┘        │ 날짜 범위    │  │
│ ┌──────────────────┐                │ 액션 타입    │  │
│ │날짜: 02-01~02-21 ✕│                │ 대상 타입    │  │
│ └──────────────────┘                └──────────────┘  │
│                                                          │
│ 프리셋: [이번 주 신규 ▾] [내 담당만 ▾] [+ 현재 필터 저장]  │
└──────────────────────────────────────────────────────────┘
```

**기대 효과:** 4개 테이블의 필터 학습 비용을 1회로 줄이고, 프리셋으로 반복 필터 작업을 제거합니다. 특히 감사로그에서 6개 필터를 다루는 관리자의 인지 부하를 크게 줄입니다.

## 개선안 5: 컨설턴트 대시보드 KPI 카드에 트렌드 & 비교 데이터 추가 🟢 쉬움

**위치:** 컨설턴트 > 대시보드 (홈)
**해당 파일:** `src/app/(dashboard)/consultant/home/_components/SummaryCards.tsx`, `src/app/(dashboard)/consultant/home/_components/StatusDistributionChart.tsx`

**현재 문제:**
`SummaryCards.tsx`에서 5개 KPI 카드(전체, 인터뷰대기, 인터뷰완료, 로드맵작성중, 로드맵완료)가 **현재 숫자만 표시**합니다. 왼쪽 테두리 4px 색상 + 우측 아이콘으로 시각적 구분은 되어 있지만, "이번 달 대비 지난달 몇 건 증가했는지", "목표 대비 진행률이 어떤지"에 대한 맥락 정보가 전혀 없습니다. `StatusDistributionChart.tsx`의 도넛 차트도 현재 스냅샷만 보여주고, 시간 경과에 따른 추이를 파악할 수 없습니다. 컨설턴트가 "이번 달 성과가 좋은 건지, 나쁜 건지"를 판단할 기준이 없습니다.

**개선 방향:**
각 KPI 카드에 **전월 대비 증감 지표**와 **미니 스파크라인**(최근 6개월 추이)을 추가합니다. 증가는 초록색 ↑, 감소는 빨간색 ↓, 변동 없음은 회색 →로 표시합니다. 도넛 차트 옆에 **월별 완료 추이 라인 차트**를 추가하여 시간 축 데이터를 제공합니다.

**참고 레퍼런스:** Mixpanel의 **KPI 카드 + 스파크라인 패턴** — 핵심 지표 옆에 thumbnail 크기 트렌드 라인을 표시하여 방향성을 즉시 파악. Vercel Dashboard의 **분산 지표(variance indicator)** — 배포 성공률을 전주 대비 증감으로 표시.

**현재 vs 개선안 시각 비교:**

```
[현재 — SummaryCards]
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│▌전체     │ │▌인터뷰   │ │▌인터뷰   │ │▌로드맵   │ │▌로드맵   │
│▌         │ │▌대기     │ │▌완료     │ │▌작성중   │ │▌완료     │
│▌         │ │▌         │ │▌         │ │▌         │ │▌         │
│▌  12  📋 │ │▌   3  ⏳ │ │▌   5  ✅ │ │▌   2  📝 │ │▌   2  🎯 │
│▌         │ │▌         │ │▌         │ │▌         │ │▌         │
└──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘

[개선안 — 트렌드 + 비교 데이터 추가]
┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│▌전체 프로젝트 │ │▌인터뷰 대기   │ │▌인터뷰 완료   │ │▌로드맵 완료   │
│▌             │ │▌             │ │▌             │ │▌             │
│▌  12     📋  │ │▌   3     ⏳  │ │▌   5     ✅  │ │▌   2     🎯  │
│▌  ↑ 3 (전월) │ │▌  → 0 (전월) │ │▌  ↑ 2 (전월) │ │▌  ↑ 1 (전월) │
│▌             │ │▌             │ │▌             │ │▌             │
│▌  ╱╲         │ │▌  ──╱──      │ │▌      ╱╱     │ │▌    ╱╱       │
│▌ ╱  ╲╱       │ │▌ ╱          │ │▌  ───╱       │ │▌ ──╱         │
│▌ 6개월 추이   │ │▌ 6개월 추이  │ │▌ 6개월 추이   │ │▌ 6개월 추이   │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
  초록 ↑ +33%     회색 → 0%       초록 ↑ +67%      초록 ↑ +100%
```

**기대 효과:** 컨설턴트가 자신의 성과 추이를 즉시 파악하여 업무 우선순위를 조정할 수 있고, 운영관리자는 컨설턴트 생산성을 한눈에 비교할 수 있습니다.
