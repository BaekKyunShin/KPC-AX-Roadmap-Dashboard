### 15. ✅ recordLLMUsage select→update/insert race condition

- **심각도:** ✅ 수정완료 (2026-02-16)
- **위치:** `src/lib/services/quota.ts:147-183`
- **문제:** `recordLLMUsage`가 SELECT → 존재 여부 확인 → UPDATE 또는 INSERT 패턴을 사용. 동시 호출 시 두 요청이 모두 `existing=null`을 받으면 2개의 레코드가 생성되어 사용량 추적이 불가능해짐
- **재현 방법:**
  1. 같은 사용자가 같은 날에 두 개의 LLM 호출을 동시에 트리거
  2. 두 요청 모두 SELECT에서 `existing = null` 반환
  3. 두 요청 모두 INSERT → 같은 (user_id, date)에 2개 레코드 생성
- **권장 수정:** DB에 `UNIQUE(user_id, date)` 제약조건 추가 + `ON CONFLICT UPDATE` upsert 패턴 사용
- **수정 내용:** `recordLLMUsage`는 커밋 `fcaf5a9`에서 원자적 RPC `check_and_increment_llm_usage`로 대체 완료 (`UNIQUE(user_id, date)` + `ON CONFLICT DO NOTHING` + `FOR UPDATE` 잠금). 추가로 동일 안티패턴이 남아있던 `fetchUserQuota`와 `updateUserQuota`도 `upsert(ignoreDuplicates: true)` 패턴으로 전환하여 `user_quotas` 테이블의 SELECT→INSERT race condition도 제거
- **공수:** M
