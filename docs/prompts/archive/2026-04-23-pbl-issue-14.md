### 🔁 5분 루프 모니터링 (필수 — loop 스킬 사용)

PR 생성 직후 **반드시 `loop` 스킬로 5분 간격 모니터링을 시작**한다.
스스로 종료 판단하지 말고 **모든 GitHub check 가 pass 할 때까지 loop 지속**.

```
/loop 5m 이 PR 의 CI 상태를 `gh pr checks <PR번호>` 로 확인해줘.
모든 check (Lint & Typecheck · Unit Test · Build · E2E Test · Vercel) 가 pass 일 때만 "✅ 통과" 로 보고하고 loop 을 종료한다.
하나라도 fail 이면 실패 로그(`gh run view <run-id> --log-failed`)를 가져와 근본 원인 분석 후 수정안을 제시한 뒤, 내가 승인하면 수정 커밋을 푸시하고 다시 loop 를 계속한다.
진행 중(in_progress / queued) check 가 있으면 "⏳ 대기 (진행 중 check 나열)" 로 보고하고 다음 틱을 기다린다.
Unit Test 만 pass 했다고 단정 금지 — E2E Test 는 별도 job 으로 가장 마지막에 실행된다.
임의로 skip·임계값 완화·--no-verify 금지. 근본 원인 해결만 허용.
```

### CI 통과 판정 규칙 (엄수)
- `gh pr checks <PR>` 출력의 **모든 check** 가 pass 일 때만 ✅
- `gh pr checks` 의 exit code 0 ≠ 모든 check pass (진행 중 시에도 비-0 반환 가능) → 출력 파싱이 정답
- E2E Test fail 시: 실패 spec 이름·스크린샷·video 아티팩트 확인 → 로컬 재현 → 근본 원인 수정 → 재푸시 → loop 재개
