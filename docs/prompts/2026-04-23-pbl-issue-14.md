## 사전 설계 결정 (Plan Mode 에서 확정)

다음을 먼저 결정해야 코드 작업 가능:

### 1. 어느 PBL 스텝에 첨부 자리를 둘지

PBL 9스텝 (`src/lib/schemas/interview-pbl.ts` + `_components/pbl/Step*.tsx` 9개):
1. StepPBLCourseOverview — 과정 개요
2. StepPBLCompanyStatus — 기업 현황
3. StepPBLProblemDefinition — 문제 정의 ← **후보 1**
4. StepPBLTargetTasks — 대상 과업 ← **후보 2**
5. StepPBLPerformanceActivities — 수행 활동 ← **후보 3**
6. StepPBLTrainingEnvironment — 훈련 환경
7. StepPBLAILevel — AI 수준 진단
8. StepPBLHrdNecessity — HRD 필요도
9. StepPBLSummary — 확인·제출

**결정 사항**:
- 산인공 양식 2번 (PBL 보고서) 의 어느 섹션이 "참고자료 첨부" 에 해당하는지
  `docs/references/2.AI PBL 과정개발보고서 및 결과보고서(양식).pdf` 직접 검토
- 가능하면 1개 스텝에 attachment_files 통합. 여러 스텝에 분산 시 LLM 프롬프트
  처리 복잡도 ↑ (양식 2번 구조에 맞춰 결정)
- 담당자 확정이 필요한지 (사용자 confirm)

### 2. 스키마 확장 위치

- `pblInterviewSchema` 에 attachment 필드 추가 위치:
  - 옵션 A: 결정한 스텝의 sub-schema 안에 `attachment_files: hrdReportAttachmentSchema[]`
  - 옵션 B: 루트 레벨에 `attachment_files: hrdReportAttachmentSchema[]` (스텝과 무관)
- DB 마이그 불필요 (interviews.pbl_data JSONB 안에 저장)

### 3. LLM 프롬프트 통합

- `src/lib/services/pbl/pbl-prompts.ts` (정확한 파일은 `find_symbol`/grep 으로
  확인) 의 어느 섹션에 attachment_files 를 병합할지
- ROADMAP 의 `formatAttachmentBody` XML 태그 sanitize 패턴 그대로 재사용 (DRY 위해
  공용 헬퍼로 추출 권장)
