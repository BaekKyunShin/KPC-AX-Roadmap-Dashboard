## 메타

- **조사일**: 2026-05-16
- **조사 범위**: 전체 시스템 (영역 인자 없음) — 공통 레이아웃·네비, 컨설턴트 워크플로우, 운영자·인증·공통 3영역 전수
- **조사 방법**: Explore 에이전트 3대 병렬 조사 → 핵심 파일 직접 확인으로 정합성 검증
- **선별 기준**: 별점 내림차순 상위 5건. 빈도·영향이 작거나 이미 해결된 결함은 제외. 사소한 마진·색상·타이포 결함은 의도적 제외
- **선정 결과**: ★★★★ 1건 + ★★★ 4건 = **CRITICAL 5건**
- **제외된 후보 (이미 코드에서 해결됨)**: 인터뷰 자동저장 가시성(PR #003), 인터뷰 review 페이지 stale 배너(PR5 R6), 로드맵 최종 확정 AlertDialog(`#2` 주석), `(dashboard)/error.tsx` 공통 폴백, login 페이지 `password-changed` 파라미터 처리
- **총평**: 시스템 핵심 워크플로우(인터뷰 → 결과 → 최종 확정)에서 데이터 손실·비가역 실수 방지는 이미 견고한 수준에 도달. 다음 사이클의 critical은 운영자 효율 가속기(자동매칭 근거 노출·일괄 처리)와 신규 사용자 첫 진입 경험(미승인 상태 안내)에 집중되어 있다.

## Nielsen 10가지 휴리스틱 (참조표)

| 번호 | 명칭 | 한 줄 정의 |
| --- | --- | --- |
| H1 | 시스템 상태의 가시성 | 사용자가 지금 시스템이 무엇을 하는지 알 수 있어야 한다 |
| H2 | 시스템과 현실 세계의 일치 | 사용자가 쓰는 언어·개념과 시스템이 일치해야 한다 |
| H3 | 사용자 통제와 자유 | 실수했을 때 빠져나올 수 있는 비상구가 있어야 한다 |
| H4 | 일관성과 표준 | 같은 의미는 같은 방식으로 표현해야 한다 |
| H5 | 오류 예방 | 위험한 액션은 발생하지 않게 막는 것이 우선이다 |
| H6 | 회상보다 인식 | 기억에 의존하지 않고 화면이 보여주어야 한다 |
| H7 | 사용의 유연성과 효율성 | 숙련 사용자에게 가속기를 제공해야 한다 |
| H8 | 미적이고 최소한의 디자인 | 불필요한 정보는 제거해야 한다 |
| H9 | 오류 인식·진단·복구 | 오류를 명확히 알리고 해결 방법을 안내해야 한다 |
| H10 | 도움말과 문서화 | 필요할 때 발견할 수 있는 도움말이 있어야 한다 |

## 보고서 읽는 법 (5단 포맷)

각 이슈는 다음 다섯 단으로 작성한다.

1. **위치** — 메뉴 경로 + 파일 경로(라인번호)
2. **사용자 시나리오** — 페르소나·동선·체감 결함 스토리텔링 (비개발자 톤)
3. **위배 원칙** — `**H{번호} {명칭}**` 굵게
4. **사용자 관점 개선 후** — 실제 노출 라벨까지 따옴표로 묘사 + `[이전]` / `[이후]` ASCII mockup 두 블록 (≤70 컬럼)
5. **개발자 구현 노트** — 변경 위치·재사용 가능 자산·짧은 구현 가이드
