로드맵·PBL 인터뷰 단순 결함을 PR 한 개로 일괄 수정해줘.

## 입력
- docs/plans/2026-04-29-roadmap-review-findings.md (검수 결과, 단일 진실 원천)

## 공통 진행 규칙
1. 시작 시 findings.md 를 먼저 읽고 본 라운드 범위 + 이미 [해결됨] 표시된 항목 + 다른 라운드 메모 확인
2. 작업 중 신규 결함 발견 시 findings.md 의 "## 추가 발견 사항" 섹션(없으면 신설)에 #NN 형식으로 추가
3. 작업 중 다른 라운드 항목에 영향 주는 사실 발견 시 해당 항목 본문 끝에 "> 메모(YYYY-MM-DD, R2로부터 발견): 내용" 추가
4. PR 머지 직전: 본 PR 이 닫는 항목 모두에 [해결됨][PR #N] YYYY-MM-DD 표기 + 같은 PR diff 안에 findings.md 변경 포함
5. 머지는 사용자 명시 승인("머지해") 후에만 진행

## 본 라운드 (R2) 범위
- #1 인터뷰 부제 '(양식 1:1 정합)' 삭제
- #2 로마자/숫자 폰트 통일 (로드맵·PBL 인터뷰 모든 항목)
- #3 Ⅰ-2 수행 일시·내용 폼 높이 표 칸과 일치
- #7 Ⅱ-2 4개 항목 폼 높이 1.7배
- #8 Ⅱ-3 표 내 폼 높이 2.5배
- #11 Ⅱ-4 표 내 폼 높이 2배
- #14 Ⅰ-3 수립 주요 결과 표 형태로 정리
- #15 Ⅲ-2 수준 영문 → 한글 (초급/중급/고급)
- 공통-C AI 로드맵 생성 99% 단계 +15초

## 브랜치/PR
- 브랜치: feat/roadmap-pbl-quick-fixes
- PR 제목: feat: 로드맵·PBL 인터뷰 단순 결함 일괄 수정
- PR 본문에 닫는 검수 항목 번호(#1 등) 명시

## 절차
1. 각 항목에 PBL/운영관리자/시스템관리자 동일 코드 경로 grep 확인 → 있으면 함께 수정 (단, 명칭 변경은 R3 범위이므로 본 라운드에서는 시각·UX 만)
2. TDD (스타일 변경은 시각 회귀 테스트로 대체 가능)
3. npm run validate && npm run build pass
4. PR 생성 → gh pr checks 의 모든 check (Lint·Unit·Build·E2E·Vercel) pass 까지 모니터링
5. 모두 pass 면 findings.md 업데이트([해결됨][PR #N] 표기) 후 같은 PR 에 push
6. 보고만. 머지는 내 "머지해" 후에 진행.
